# TASC project: RUNTIME routines (Phase R, part 2)

Addresses for RUNTIME 2.01 at $0803 (see `docs/runtime/runtime_listing.txt`). Status "observed" = read from the listing; "confirmed" = also measured in Pandowdy. Zero page: IACC $A0 (hi) / $A1 (lo), IARG $9E/$9F, loaded string $77/$78, pushed string $79/$7A, CURLIN $75/$76 (holds object-code addresses in compiled programs).

## [observed] Integer multiply (int op4, $0BC8) and the shared multiply loop

Op4 of RT.DISP.INT loads the variable into IARG, makes IARG and IACC positive (counting negations in $AB; negating -32768 overflows to error $45), then multiplies by shift-and-add ($0C14-$0C3D) into IACC, raising error $45 (OVERFLOW) if a partial product sets bit 15; finally, if exactly one operand was negative, it negates the result through RT.INEG. The same loop is entered at $0BF6 with $16 as a flag by the array code to scale a subscript offset (offset * (max index + 1)); BIT $16 at $0C45 sends that path back into the array loop.

## [observed] Arrays: RT.ARR.REAL/STR/INT ($0B11/$0B14/$0B17) and RT.ARR.STORE ($0C6F)

Each array's access routine is `SEC|CLC, JSR disp` followed by an inline descriptor [address][ndims][max index]* (rightmost first). The three entries set X = element type (0 real, 2 string, 1 int; BIT-skip) and save the carry (1 = load, 0 = element address) in $64, type in $65. The routine pops its return address to reach the descriptor ($55/$56) and the compiled caller's return address ($83/$84, pushed back before returning). The first subscript is in IACC; further subscripts were pushed by RT.PUSH.SUBSCRIPT ($165C real, AYINT first / $165F int). For each dimension: bounds check against the max index (error $6B BAD SUBSCRIPT, so negative or too large subscripts fail), offset = offset * (max+1) + subscript. The offset is scaled by 5 (real) or 2 (int, string) and added to the base address. Load: real -> LOAD.FAC.FROM.YA + flags; int -> int op0; string -> pointer into $77/$78 and $79/$7A. Address: element address to $DC/$DD, type to $D9, then RTS to the compiled code, which evaluates the right-hand side and calls RT.ARR.STORE: real -> STORE.FAC.AT.YX.ROUNDED, int -> int op1 (store IACC), string -> string store ($77/$78 into the element).

## [confirmed] FOR/NEXT frames, RETURN through FOR frames, POP

Measured in Pandowdy (objects p1_mixed/flow.for_step and p1_more/rem.int_for): RT.INIT resets SP to $FD; each FOR pushes a 16-byte frame. Real loop (low address first): +0/+1 marker $09B0 (the value of the FOR-pop vector $AF/$B0), +2/+3 loop address - 1, +4..+8 STEP (packed real), +9..+13 LIMIT (packed real), +14/+15 address of the loop variable. Integer loop (INTEGER-declared variable): +0/+1 marker, +3 = 0 (tells NEXT it is an integer loop; a real frame has the loop address high byte there), +4/+5 STEP (high byte first), +7/+8 loop address - 1, +9/+10 LIMIT, +14/+15 variable address; +2, +6, +11..+13 unused. RT.FOR.INIT ($09E8, $09E5 floats IACC first; integer $09E1, $09DE converts FAC with AYINT) stores the initial value into the variable named by the inline word and removes any existing frame for the same variable; LIMIT/STEP ($16BF/$16B8, STEP1 $16AC loads 1.0 from the ROM constant CON.ONE $E913; integer $1691/$168A/$167E) push the values under the caller's return address. RT.NEXT ($0A31) takes an inline variable address (0 = innermost loop), discards frames until it finds the variable's (as Applesoft does), adds STEP (real: FADD, store; int: add with overflow error $45), compares with LIMIT taking the sign of STEP into account, and either re-enters the loop (pushes the loop address and RTS) or drops the frame and continues after its inline word. Trick: the marker $09B0 is also a valid return address, so when a subroutine executes RTS (RETURN) with its own FOR frames still on the stack, the RTS lands at $09B1, which discards the other 14 bytes of the frame and RTSes again: RETURN unwinds unfinished loops. RT.POP ($097B) skips FOR frames to remove the GOSUB return address; with none it raises error $16 RETURN WITHOUT GOSUB ($09AD; the stub at $09B9 does the same).

## [observed] Strings: literals, printing, concatenation, garbage collection

String values are [length][text]; variables hold pointers. RT.STRLIT ($0EC5) points the loaded string ($77/$78) at the literal inside the object code (no copy) and skips its inline word; $0EC2 (prompt form) also prints it. RT.PRINTSTR ($0EEE) prints ($77). RT.PUSHSTR ($1135) moves the loaded string to the pushed slot $79/$7A; RT.CONCAT ($10EF) builds pushed + loaded in string space; RT.CONCAT.T ($10DF) swaps the two slots first. New strings are allocated downward from the bottom of string space ($6F/$70, initialised from HIMEM $73/$74 - 2) and must stay above HIGHEST ($14/$15). The collector ($0F15; FRE enters at $0F13, CLEAR CHAIN at $0F0B with $80 cleared) is compacting: its roots are the COMMON string block ($6B+1..$6D), the local string variables ($7D+1..$7F) and both string slots ($77/$78, $79/$7A); each pass finds the highest live string below the moving top ($95/$96), copies it to the top and rewrites every pointer to its old address ($66 = $80 marks the rewrite pass). Literals in the object code lie below string space and are never moved. FRE returns $6F - $14. Running out of space raises error $4D OUT OF MEMORY. String functions (LEFT$ $11C4, RIGHT$ $11F2, MID$ $1227/$1231, STR$ $11A9, CHR$ $1192, VAL $0E80, LEN $0EB6, ASC $0EAA) and comparisons ($1532, $1582, $15B7, $1546, $1549, $152F) work on these two slots.

## [observed] INPUT, READ/DATA, GET

RT.INPUT.BEGIN ($1627) saves the statement's start (return address - 2) in $50/$51. Items: numeric $12FD (first), $1300 (after a prompt), $1312 (next); string $1287/$128A/$1298. A new line is read with INLIN ($D52C) into $0200; $71 is the scan position ($FF new line, $FE consumed). Ctrl-C ($03) as the first character ends the program. Items are separated by commas; strings may be quoted. Numbers are converted by pointing TXTPTR ($B8/$B9) at the buffer and calling FIN ($EC4A); a bad number prints ?REENTER ($DB87) and restarts the whole INPUT statement through JMP ($0050) (four NOPs at $133A-$133D are patched-out bytes; RUNTIME 2.01 differs from 2.0 in 371 bytes). RT.INPUT.END ($1387) prints ?EXTRA IGNORED if input is left over. READ ($13AC number, $13A9 string) walks the DATA chain from $F6/$F7 (initialised from the header's DATAPTR): items [len][text]; $FF is followed by the link word to the next DATA block; link 0 raises error $2A OUT OF DATA; numbers go through FIN. RESTORE ($0963) resets the pointer. GET X ($1399) reads a key: a digit gives its value, anything else 0; GET A$ ($10CC) makes a 1-character string.

## [observed] STOP/END, RESUME/Debug, ONERR/RESUME and error capture

RT.STOP ($134B) puts the statement's object address (return address - 2) in CURLIN ($75/$76), prints BREAK through STROUT ($DB3A) and " IN " + CURLIN through $ED19, then falls into RT.END ($1363), which restores Applesoft's CHRGET at $B1-$C8 from the ROM copy at $F10B, clears the program pointer and returns to the interpreter ($D64B, $D566). That is why runtime errors and BREAK report object-code addresses (manual 10.2). The RESUME/Debug call RT.DEBUG ($1423) saves the stack level in $F8 (REMSTK) and the statement's object address in CURLIN before each statement. RT.ONERR ($1637) sets ERRFLG $D8 = $80 and copies the inline handler address into $5C/$5D (the JMP at $5B). The ROM's error handler saves CURLIN/stack and resumes interpretation through CHRGET; RT.INIT's CHRGET patch (15 bytes from $096C copied to $BA) contains a branch to $5B, which diverts that into the compiled handler (exact trigger condition to be confirmed by tracing an error). RT.RESUME ($1656) restores the stack pointer saved at error time ($DF) and jumps through ($00DA), the saved statement address.

## [observed] Small entries

RT.FLOAT.IACC $166E = GIVAYF ($E2F2) on IACC; RT.IMOVE $1675 IACC -> IARG; RT.ISUBT $0CDA IACC = IARG - IACC; RT.INEG $0CC3; RT.CLEARCOMMON $08A7; RT.CLEAR $08AA; RT.HIMEM $08DB (GETADR); the graphics/argument savers ($15CD-$1608) store a coordinate or byte argument for the following statement routine; RT.CALL $173B / $1738 JSRs to the address; USR is the ROM vector at $0A.
