# TASC project: Phase 1 predictor (Python model of TASC code generation)

`tasc/compiler/` (parse.py, codegen.py, assemble.py, fin.py) compiles a tokenized Applesoft program into a TASC 2.01 object file. As of session 2 it reproduces BALL.OBJ byte for byte (and its line table) and all 961 recorded compiles of the controlled families plus the first random batch (`python -m tasc.predict_check`, pytest `tests/test_compiler.py`). Rules below are those the predictor needed beyond `phase1.md`; status "confirmed" = the rule is required for byte-exact matches across the recorded compiles.

## [confirmed] Numeric constants are packed by the ROM's FIN, not correctly rounded

Evidence: experiment r1000 (p1_rand1): TASC stored 3.14159 as `82 49 0F CF 82`; the correctly rounded value is `... CF 81`. The Applesoft interpreter's own `X=3.14159` stores `82 49 0F CF 82` (checked in Pandowdy, session 2). `tasc/compiler/fin.py` translates FIN ($EC4A), MUL10, DIV10, ADDACC, FLOAT, FADDT/FADD.2-.4, SHIFT.RIGHT, NORMALIZE.FAC, ROUND.FAC, FDIVT and STORE.FAC.AT.YX.ROUNDED instruction by instruction on a zero-page model; it matches all 853 real constants in the experiments. Details that matter: SHIFT.RIGHT depends on the carry left by the caller's `CMP #$F9` and its own `ADC #8`; FADD with equal exponents adds the carry from `SBC FAC` into the extension byte; the decimal exponent is a single byte (loops run 256-e times for negative e).

## [confirmed] Symbol table: 32 buckets, entry times

Bucket for names: h = (3*(c1-1) + c2 + T) mod 32 (5-bit character codes, c2=0 for one letter), T = real 0, string 1, int 2; arrays add 22 (real 22, string 23, int 24). Names declared with REM! INTEGER become int but keep T=0, and are entered at the declaration (insertion order matters within a bucket). Constants: bucket = low byte & 31 (int, stored big-endian) or exponent & 31 (real). A numeric literal enters the table when the expression is scanned, with its natural type (int if integer constants are on and the value is an integer within ±32767, else real); a form of the other type is entered when code first needs it. Within a bucket, entries keep insertion order. Evidence: p1_order, p1_order2, p1_alloc2, PASS0/1/2 constant pools, r1011 (2.25 before real 2), r1012 (INTEGER J before N2%).

## [confirmed] Layout of locals and routines

Locals (from LOCBEG1+1): int temps, real temps, DEF FN parameters (definition order), FN-body temps (a separate pool), numeric scalars (hash order), numeric arrays (hash order); then string temps and all string symbols, scalars and arrays interleaved in one hash order. COMMON variables are excluded (they live in the COMMON block in declaration order). Routines: numeric symbols with ops (same order), constants (pool order), numeric arrays (always, even if only DIMmed), then the string section in storage order (arrays always). Array routines store the dimension list rightmost first. Evidence: BALL (int temp before real temp, int-array order), r1001 (FN temp), r1003 (string interleaving), arr_and_scalars, goto_fnassign, arr_dim2.

## [confirmed] Expression code generation follows the bottom-up parse

TASC parses a whole expression before generating code: string literal data (JMP over [len][text]) and constant-table entries are produced at scan time, in source order; code is produced at each reduction. A simple operand (variable or constant) is loaded only when its operator is reduced. There is one numeric accumulator (FAC/IACC) and one string accumulator. When a computation needs an accumulator that holds a pending result, the result is spilled to a temp of its own type (int results are not floated first). Consequences: commutative ops apply the simple operand's routine op; `-`, `/`, `^` with a complex left and simple right use MOVAF (int: $1675) then the right load then FSUBT/FDIVT/FPWRT (int: $0CDA); both complex: T.op1, right, T.op(k) (6+k for an int temp in real mode); comparisons with a simple left and complex right evaluate the right and swap the relation; AND/OR test the simple operand in memory (LDA exponent, or LDA/ORA for an int, including a constant's pool bytes). Builtin arguments: complex ones are computed as scanned (spilling as needed by the accumulators their computation uses), simple ones are loaded at the reduction; at the start of the reduction any pending result that is not the first of its class to be consumed is spilled. Subscripts likewise, pushed last to first ($165C real / $165F int), the first ending in the accumulator (AYINT if real). Strings: a complex result (array element, function, concatenation) is pushed; simple ones are loaded; CONCAT ($10EF) = pushed + loaded, CONCAT.T ($10DF) = loaded + pushed; PUSHSTR ($1135) only when both operands are simple. Evidence: p1_fill, p1_more, p1_rand1 (r1002, r1005, r1007, r1009, r1011, r1016, r1018, r1020, r1025, r1042, r1051).

## [confirmed] Flags, IF and NOT

A value just loaded or stored through a routine (real ops 0/1, int ops 0/1/6/7) or produced by a comparison/logic routine already has the flags set; otherwise IF and NOT emit `LDA $9D` (real) or `LDA $A0 / ORA $A1` (int) first. IF/NOT on an integer literal uses an int constant. `IF c THEN stmts` = c, BNE *+5, JMP next line; `IF c THEN n` / `THEN GOTO n` / `IF c GOTO n` = c, BEQ *+5, JMP n; `IF c THEN RETURN` = c, BEQ *+3, RTS. Evidence: p1_mixed/flow, p1_fill/g.if_*, BALL line 370, r1001, r1006, r1008.

## [confirmed] Dead code after an unconditional transfer

After GOTO, IF..THEN line (or THEN GOTO), RETURN (including IF..THEN RETURN), END, STOP or NEW, the rest of the line's statements that begin with a keyword token are skipped without being parsed (no code, no symbols); statements that begin with a name (implicit LET) are still compiled, and DATA is always compiled. The skip ends at a ':' outside quotes; REM skips the rest of the line. Quirk to preserve: `IF X THEN RETURN:Y=1` executes Y=1 when X is false. Evidence: p1_dead, p1_dead2, r1000, r1004, r1006, r1012.

## [confirmed] Integer entry points and other RUNTIME entries

The integer-argument variant of a statement or function entry is the real entry +3, except CALL ($173B/$1738), HIMEM: ($08DB/$08D8), POKE/WAIT address ($1741/$173E) and PEEK ($1747/$1744), which are -3. Integer FOR loops (INTEGER-declared variable) use $09E1/$1691/$168A/$167E, and the entry 3 below for a real-valued start/limit/step. String compares: = $1582, < $1532, <> $15B7, > $1549, <= $1546, >= $152F. INPUT strings: first $1287, after a prompt $128A, later $1298. INPUT/READ into an array element: element address (CLC entry), input/read routine, $0C6F. RESUME/Debug code: JSR $1423 before each statement except REM, DATA, DIM, END, GOTO, GOSUB, RETURN, HOME, TEXT, GR, HGR, HGR2, NORMAL, INVERSE, FLASH, RESUME, DEF, NEW, ONERR, STOP, RESTORE; the first statement after THEN gets none. TASC's expression parser ends a string expression at an operator invalid for strings (PRINT juxtaposition: `"TASC"-(...)`). Evidence: p1_fill, p1_more/rd.*, r1040.
