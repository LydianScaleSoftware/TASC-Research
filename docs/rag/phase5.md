## [confirmed] MAKE RUNTIME rebuilds RUNTIME byte for byte

RUNTIME is hand-written 6502 (H6), so it has no Applesoft source; Mark decided (2026-10-25) that its build step is an Applesoft program `MAKE RUNTIME` that POKEs the bytes from DATA statements and BSAVEs the file, in line with how the original was probably produced (not described in the manual). Source `src/MAKE_RUNTIME.txt` (165 lines: code at 10-40, DATA 100-1700, 25 bytes per line), `src/MAKE_RUNTIME.DOC.TXT` (line-mirrored, each DATA line's address range), `src/MAKE_RUNTIME.VARS.TXT`; generator and emulator check `python -m tasc.makeruntime`. Line 10 handles the overlap: the bytes go to $0803-$17AF where an Applesoft program normally lives, so if PEEK(104) < 64 it sets TXTTAB to $4001 (POKE 103,1: POKE 104,64: POKE 16384,0) and re-runs itself with PRINT CHR$(4);"RUN MAKE RUNTIME". Line 20 `FOR AD = 2051 TO 6063: READ BY: POKE AD,BY`, line 30 `BSAVE RUNTIME,A$803,L4013` (BSAVE needs the length too, and records the address it saves from, so the bytes must be at $0803). Evidence: experiments/p5_makeruntime/summary.json: on a copy of the TASC 2.01 disk with RUNTIME deleted (HELLO's BLOAD RUNTIME then stops at FILE NOT FOUND, so TASC never runs and DOS is unpatched), RUN MAKE RUNTIME produced RUNTIME, B file at $0803, 4,013 bytes, sha256 3982a702..., identical to the original, in 62M cycles. pytest test_make_runtime_listing checks the DATA bytes and the DOC line mirror without the emulator.
