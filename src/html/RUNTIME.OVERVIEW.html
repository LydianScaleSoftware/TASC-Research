RUNTIME: the library compiled programs call

What it is

RUNTIME is 4013 bytes of 6502 machine language, normally loaded at $0803-$17AF with BLOAD RUNTIME before a compiled program is run with BRUN. Compiled code is mostly calls: almost every statement, operator and function becomes a JSR into RUNTIME or into the Applesoft ROM, after code that loads the operands. RUNTIME keeps everything the ROM does not provide: integer arithmetic, the variable dispatchers, arrays, FOR/NEXT, the string routines and garbage collector, INPUT and READ, COMMON, ONERR/RESUME, and small entries that check an argument and go on into the ROM's own code for a statement.

The source (RUNTIME.S) is written for Apple's DOS Toolkit assembler and assembles to the library byte for byte.

Starting a program

Every object file starts with JSR INIT and a 17-byte header (INIT). INIT:

  • points the & vector at the program, so & runs it again;
  • puts JMP instructions at $58 (to FLOATI, which floats the integer accumulator) and $5B (the ONERR handler);
  • learns the library's own address from the operand of the caller's JSR and computes the addresses it stores from it;
  • copies a 15-byte patch over CHRGET (CHRPATCH) that lets the ROM's error handler reach a compiled ONERR handler;
  • copies the header to page zero: the first DATA item ($12), the highest address ($14), the COMMON bounds ($69-$6E) and the local bounds ($7B-$80). A program that declares USECOMMON checks that the COMMON bounds are those the previous program left (otherwise error 163, TYPE MISMATCH);
  • clears the variables (CLEAR) and resets the stack (RESETSTK), leaving a return address to NORET at the bottom so a RETURN without GOSUB is caught.

How compiled code calls it

Accumulators. Real values are in Applesoft's FAC ($9D-$A2), with ARG ($A5-$AA) as the second operand. Integers are in IACC ($A0 high, $A1 low; these are FAC+3 and FAC+4, which is where AYINT leaves its result) and IARG ($9E/$9F). Strings are pointers to [length][text]: the loaded string at $77/$78 and the pushed string at $79/$7A.

Real and integer entries. A routine that takes a number usually has two entries 3 bytes apart. The real entry is JSR AYINT (or for an address JSR $58, which floats IACC), and the code generator uses whichever matches the operand's type. Byte arguments go through the ROM's CONINT (error ILLEGAL QUANTITY above 255); addresses through GETADR.

Inline operands. Some calls are followed by data the routine reads through its return address and then returns past: the loop variable's address after the loop start and NEXT; a literal's address after STRLIT; the handler's address after ONERR; a count and line addresses after ON GOTO/GOSUB; an array's descriptor after the array dispatchers.

Variables. Compiled code reaches every variable through a small routine of its own, which loads an operation number and the variable's address and jumps to a dispatcher:

Memory and strings

String space runs down from HIMEM; $6F/$70 is its bottom. New strings are made below it (NEWSTR); when there is no room the garbage collector (GARBAG) packs the strings still in use at the top. Its roots are the COMMON strings, the local strings and the two string accumulators; literals and DATA items stay where they are in the program. An empty string is kept at HIMEM-1, and cleared string variables point at it. REM! CLEAR CHAIN (CLRCHAIN) collects garbage keeping only the COMMON strings, then clears the locals, ready for BRUN of the next program.

FOR loops

The loop start stores the initial value and pushes the variable's address; the limit and step push the rest. A frame is 16 bytes, from the top of the stack:

The marker is also a valid return address: a subroutine that RETURNs with loops still open lands at FORUNWND, which drops the frame and returns again. NEXT finds the variable's frame, dropping inner loops, adds the step and compares with the limit in the step's direction. POP passes over frames to drop a GOSUB return.

Errors

Every error ends at ERREXIT with Applesoft's error number in X. Without ONERR the object address of the failing call becomes the "line number" of the message, so errors report addresses in the compiled program. With ONERR the patched CHRGET passes control to the handler, and RESUME (with the RESUME/debug option, which puts DEBUG before every statement) restarts the failing statement.
