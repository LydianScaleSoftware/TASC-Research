AASCAD

All programs Manual AASCAD

AASCAD, Another AppleSoft Compiler And Decompiler, is a reimplementation of TASC 2.01 as one Python script. It compiles an Applesoft program exactly as TASC does, producing the same object file byte for byte, and it turns a TASC object file back into an Applesoft program, which it checks by compiling it again: a decompiled program is reported only if it compiles to the same bytes.

Download aascad.py (253,919 bytes, sha256 4c6aff552ec807c3…)

Needs Python 3.9 or later and nothing else: no packages to install. Reading and writing disk images also needs CiderPress II’s command-line program.

The project’s details, history and tests: project page on GitHub.

compile

aascad compile SOURCE [-o OBJECT] [options]. TASC’s questions become options; leaving one out is the same as answering it with RETURN. Prints the object’s load address, size and SHA-256.

OptionMeaning
SOURCEthe Applesoft program: a text listing (numbered lines) or a tokenized program as DOS saves it
-o OBJECTthe object file to write (default: the source’s name with .OBJ)
--library ADDRwhere RUNTIME is loaded (TASC’s memory usage question; default $0803)
--program ADDR|HGR1|HGR2where the compiled program goes (default: right after the library); HGR1 or HGR2 starts it above that hi-res screen
--variables ADDRwhere the program’s variables go (default: right after the program)
--no-int-arithturn off the integer arithmetic option
--no-int-constturn off the integer constants option
--resumeturn on the RESUME/debug code option
--compare OBJECTcheck the result against an existing object file, byte for byte
--mapprint the line number table: each line and its object code address
--replaceallow replacing a file that is already on a disk image

decompile

aascad decompile OBJECT [-o LISTING] [--bas PROGRAM]. The memory layout comes from the object’s header; the code options are found by trying each combination until the recompiled program matches.

OptionMeaning
OBJECTa TASC object file
-o LISTINGwrite the Applesoft listing here (default: print it)
--bas PROGRAMalso write the tokenized Applesoft program
--load ADDRthe object’s load address, if it can’t be found (a file from a disk image brings its own; otherwise it is read from the object’s header)
--replaceallow replacing a file that is already on a disk image

Files and disk images

Files are read from and written to the local filesystem. A file inside a DOS 3.3 disk image is named IMAGE::NAME, for example TASC.dsk::BALL. Images are handled by CiderPress II’s command-line program, found through --cp2 PATH (given before the command), the CP2PATH environment variable, or cp2 on the PATH. An object written to an image is a binary file at its load address; a listing or --bas program is an Applesoft file. A file already on the image is replaced only with --replace.

Addresses may be decimal, $hex or 0xhex.

Examples

python3 aascad.py compile BALL.txt -o BALL.OBJ
python3 aascad.py compile BALL.txt --no-int-arith --compare ORIGINAL.OBJ
python3 aascad.py decompile BALL.OBJ -o BALL.txt --bas BALL.bas
python3 aascad.py compile "TASC.dsk::BALL" -o "WORK.dsk::BALL.OBJ"
python3 aascad.py --cp2 /opt/cp2/cp2 decompile "TASC.dsk::PASS1" -o PASS1.txt
python3 aascad.py compile --help
